## 배경 및 문제
- 기존 프롬은 알림 미리보기 설정만 있고 **알림음 선택 기능 없음**
- 경쟁 서비스(버블)·카카오톡 대비 개인화 설정 부족
- 운영 반영 마감(10/26)이 고정 → **스토어 심사 기간을 역산한 일정 관리**가 핵심

## 담당 범위 및 진행
| 버전 | 내용 |
|---|---|
| v0.1 | Figma 디자인안·현행 구조·타 플랫폼 레퍼런스로 초안 |
| v0.2 | 프롬 현행 화면, 버블, 카카오톡 실캡처로 레퍼런스 구체화 |
| v0.3 | 식별값·개발 상세 제거, 기획 문서 톤으로 정리 |
| v0.4 | 10/26 운영 반영 → **10/19 스토어 심사 제출** 역산 일정 반영 |

- PRD(범위·일정·우선순위)와 **정책정의서(화면별 정책·예외)를 분리** 작성
- 화면설계서: Figma 기반 표지 + 5개 화면

## 핵심 의사결정
- 범위: 팬앱(iOS·Android)만. 아티스트앱·매니저앱·웹·어드민 제외
- 알림음 6종(기본 + 스타일 5종)
- 음원 소싱: Pixabay·Freesound·ZapSplat·Mixkit 라이선스 비교 → Pixabay 기준 상업 사용 가능·출처표기 불필요, 단 가공 사용 권장·브랜드 시그니처음 사용 불가 확인
- 카테고리(팝·차임/벨·악기 멜로디·귀여운 소리·미니멀)별 후보 및 이름 제안(톡/딩동/마림바/하프/반짝)

## 문제 해결 사례

**① 최종 디자인에서 누락 정책 발견 → 역반영**
- 화면설계 중 Figma 최종안에서 기존 정책에 없던 **알림 전체 ON/OFF 토글** 발견 → 정책정의서에 추가

**② 화면 기준 정책 재점검**
- 화면설계서 완성 후 정책정의서를 화면 기준으로 전수 대조 → **불일치 5건 수정** 후 개발 전달

**③ 미결 사항을 담당자·기한으로 관리**
- 푸시 반영 방식(iOS 서버 전달 vs 앱 처리, Android 알림 채널 전환)
- 전체 ON/OFF 토글 정책, 선택 표시 방식(라디오/체크), 설정 화면 '알림' 상태값 기준
