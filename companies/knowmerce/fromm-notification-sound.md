## 핵심 의사결정
- 범위: 팬앱(iOS·Android)만. 아티스트앱·매니저앱·웹·어드민 제외
- 알림음 6종(기본 + 스타일 5종)
- 음원 소싱: Pixabay·Freesound·ZapSplat·Mixkit 라이선스 비교 → Pixabay 기준 상업 사용 가능·출처표기 불필요, 단 가공 사용 권장·브랜드 시그니처음 사용 불가 확인
- 카테고리(팝·차임/벨·악기 멜로디·귀여운 소리·미니멀)별 후보 및 이름 제안(톡/딩동/마림바/하프/반짝)
- 앱 알림 토글 초기값 ON. 기기(OS) 알림 OFF 시 앱 화면의 알림 토글을 OFF로 표시 — 표시 방식은 팀(디자인·개발) 결정, **표시만 OFF로 하고 저장값은 유지해 기기 알림 재허용 시 자동 복원**하는 해석은 내 제안 `[확인 필요: 표시만 OFF인지 저장값까지 OFF인지 최종 확정]`
- 설정 화면 '알림' 상태값: 기기 알림·앱 알림이 모두 ON일 때만 '켬'. 현행은 미리보기 토글 기준이었음을 디자인 담당 확인으로 파악, 업데이트하지 않은 사용자는 기존 동작 유지

## 문제 해결 사례

**① 최종 디자인에서 누락 정책 발견 → 역반영**
- 화면설계 중 Figma 최종안에서 기존 정책에 없던 **알림 전체 ON/OFF 토글** 발견 → 정책정의서에 추가

**② 화면 기준 정책 재점검**
- 화면설계서 완성 후 정책정의서를 화면 기준으로 전수 대조 → **불일치 5건 수정** 후 개발 전달

**③ 미결 사항을 담당자·기한으로 관리**
- 푸시 반영 방식(iOS 서버 전달 vs 앱 처리, Android 알림 채널 전환)
- 전체 ON/OFF 토글 정책, 선택 표시 방식(라디오/체크) — 설정 화면 '알림' 상태값 기준은 10/15 확정

**④ 기기 알림 OFF 신규 화면 → 정책 신설**
- 디자인에서 기기 알림이 꺼진 경우의 안내 영역('기기 알림 켜기' 버튼)이 추가됨 (팀)
- 정책 신설 (내 작업): 노출 조건, 확인 시점(화면 진입·기기 설정에서 복귀), 버튼 동작, 복귀 시 상태, '앱 알림만 OFF'와의 구분, 항목 순서·명칭 변경 반영, QA 시나리오 추가
- 새 미결 3건을 담당·기한과 함께 등록: 알림음 기본값 표기 문구, iOS 최초 권한 요청 전 버튼 동작, Android 일부 알림 종류만 꺼진 경우

**⑤ 팀 결정 변경에 따른 정책 수정**
- 동료 질문(초기값, 기기 알림 거부 시 앱 토글 자동 OFF 여부)에 정책 기준으로 답변
- 이후 팀이 '기기 알림 OFF 시 앱 화면에도 OFF로 표시'로 결정 → 저장값까지 OFF로 바꾸면 기기 알림을 다시 켜도 알림이 오지 않아 문의가 생길 수 있다고 판단
- **표시만 OFF·저장값 유지·재허용 시 자동 복원**으로 정책에 반영하고, 앞선 답변 정정 공유 `[확인 필요: 팀 최종 확정]`
