# FCOSTYLE — FC온라인 데이터 분석 서비스

> 정리 기준일: 2026-10-16 · 작성 규칙: 레포 루트 CLAUDE.md
> `[확인 필요]` 항목은 사실 확인 전 이력서·면접에 사용하지 않는다.

## 1. 시작 배경
- 목표: 광고 수익형 웹사이트로 부업 수익 만들기.
- 주제 선정: IT·PM 인사이트, 재테크, 여행, 기기 리뷰, 스포츠베팅 분석 등을 **ICE로 비교**. 스포츠베팅은 애드센스 정책 리스크로 제외. 수익 구조(트래픽 × 페이지뷰 × RPM)와 트래픽 규모별 예상 수익도 계산.
- 인터랙티브 진단 콘텐츠의 장단점을 따져 **재미(진단) + 실데이터(분석) 결합** 방향으로 FC온라인 선택.

## 2. 문제 정의와 차별점
- 문제: 유저가 자기 플레이 스타일을 객관적으로 알 방법이 없음. 선수 추천은 커뮤니티 통설 위주. 기존 전적검색 사이트는 스탯만 보여주고 해석이 없음.
- 기회: Nexon Open API가 전체 유저 카드 사용률 같은 집계를 제공하지 않음 → **상위 랭커 표본 수집으로 공백을 메움**.
- 차별점: 실데이터 기반 / 자기 개선형 피드백 / "실제 축구 기준" 큐레이션과 "FC온라인 기준" 실측을 섞지 않고 구분 / 시즌 변경 시 카드 정보 자동 최신화

## 3. 타겟 세그먼트
| 세그먼트 | 니즈 | 대응 기능 |
|---|---|---|
| 라이트 유저 | 재미 위주 진단 | 팀컬러 진단 |
| 실사용자 | 내 경기 데이터 기반 분석·개선점 | 실제 매치 기록 진단 |
| 스쿼드 고민 유저 | 포지션별 선수 선택 | 선수 진단, 랭커 정보, 카드-포지션 체크, 스쿼드 체크 |
| 상위권 유저 | 랭커·프로게이머 벤치마크 | 랭커 정보, 프로게이머 비교, 시즌 트렌드 |

## 4. 주요 기능
- **실제 매치 기록 진단(핵심)**: 최근 공식경기 최대 20경기 → 승률, 플레이스타일 배지, 슈팅 히트맵, 전략적 피드백(22개 실계정 표본으로 임계값 보정), 나 vs 랭커 35명 vs 프로게이머 22명 비교, 가장 비슷한 프로게이머 매칭, 포메이션별 성과, 스쿼드 기준 추천, 스쿼드 랭커 메타 일치율
- **커스텀매치 상대 전적**, **선수 진단**(2트랙), **팀컬러 진단**(DISC 20문항, 12개 유형)
- **랭커 정보**, **포지션별 카드 티어리스트**, **시즌 메타 변화**
- **카드-포지션 실시간 체크**, **스쿼드 전체 실시간 체크**(닉네임 자동 불러오기)
- **공유**: 링크 복사, 이미지 저장, 결과별 동적 공유 이미지

## 5. 데이터 설계
- 실시간: Nexon Open API
- 정적 스냅샷: 랭커 수집 파이프라인 직접 구축, 61명 → UC 시즌 후 재실행으로 **74명** 갱신
- 큐레이션: 기존 108건 + 라이브 검증 49건 = 156건
- 데이터 품질: 신규 49건 전수 재검증, 실사용 미확인 26건 교체

## 6. 정책 설계
- **데이터 신뢰도 게이팅**: 최근 30일 + 15경기 이상만 사용, 표본 6명 이하 목록·7명 이상 요약, 3명 미만 "참고용" 배지, 1~2명에 좌우되는 포메이션 제외
- **콘텐츠 정직성**: 근거 출처 배지 의무화, 표본 크기 병기, 소표본 지표 해석 주의 문구, 실측 트랙 성향 필터 개입 금지
- **광고**: 앵커·인페이지만 사용, 전면·의도 기반 광고 비활성화
- **배포 운영**: 로그 대조로 중복 배포 경로 실패 원인 확인 → git push 단독 배포, 이후 동일 실패 0건
- **폐기 정책 기록**: 쓰이지 않게 된 순위 가중치 정책 삭제 및 폐기 이력 문서화

## 7. 문서화
PRD, IA, 정책 정의서, 데이터 스펙, 화면 기능 정책, 와이어프레임, DISC 퀴즈 설계, 커뮤니티·프로게이머 리서치 등 총 10종

## 8. 제품 진화 (커밋 이력 기준)
초기 기획 → DISC MVP → Open API 실데이터 전환 → 랭커 데이터 → 수익화·운영 기반(도메인, 애드센스 확인, SEO, GTM, 문서화, Vitest) → 애드센스 반려 대응 → 커뮤니티 리서치 기반 확장 → UC 시즌 재수집·포지션 로직 개선

## 9. 문제 해결 사례 (STAR)
- **① 애드센스 반려 원인 진단**: "가치가 낮은 콘텐츠" 반려 → Search Console에서 다수 페이지 "발견됨-색인 생성 안 됨" 확인, 필수 정책 페이지 누락·콘텐츠 깊이 부족을 원인으로 특정 → 색인 정상화 확인, 소개·가이드·약관 페이지 신설 후 재신청 준비(결과 대기)
- **② 배포 실패 메일 원인 추적**: 성공/실패 배포 로그 대조로 파일 업로드 방식 중복 경로가 원인임을 확인 → git push 단독 배포 정책, 재발 없음
- **③ 큐레이션 데이터 신뢰성**: 신규 49명 중 26명(약 53%)이 실사용 표본 없음 → 검증 기준을 라이브 API 실사용 확인으로 변경, 26명 전원 교체, 2단계 검증 원칙화
- **④ 포지션 분류 경직성**: RW/RM 등 형제 포지션 정의, 표본 없을 때 형제 포지션 재조회 → 공통 함수 공유하는 3개 기능 동시 개선, GK·CB 등은 형제 미지정으로 과완화 방지
- **⑤ 커뮤니티 리서치 기반 기능 발굴**: 디시·에펨코리아 조사로 스쿼드·카드-포지션 질문 반복 확인, 시세는 공식 API 부재·스크래핑 리스크로 배제 → 기존 실시간 조회 구조 재사용해 신규 기능 2종 출시
