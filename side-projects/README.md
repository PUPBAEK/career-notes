## AI와 일한 방식

### 역할 분담 원칙
FC 사이트 초기 기획 문서에 처음부터 명시한 원칙: 개발/콘텐츠/데이터 분석은 Claude와 함께 진행하고, 계정 인증·결제·최종 검수·홍보는 본인이 담당한다.

| 영역 | 본인 | AI (Claude Code) |
|---|---|---|
| 문제 정의·방향 | 주제 선정, 타겟·차별점 정의, 콘텐츠 우선순위 결정 | 후보 비교표·리서치 자료 제공 |
| 리서치 | 최종 채택 여부 판단 | 공식 자료·기사·커뮤니티 교차 조사, 출처 정리 |
| 기획 문서 | 검토·결정 | PRD·IA·정책·데이터 스펙 초안 작성, 결정 사항 반영 |
| 구현 | 결과물 확인·수정 지시 | 코드 작성, 테스트 작성, 리팩터링 |
| 검증 | 실기기 확인(공유·저장·카톡 카드) | 자동 테스트, 시뮬레이션, 배포 후 크롤링 점검 |
| 리스크 판단 | 저작권·광고 정책·개인정보 고지 범위 결정 | 정책·약관 조사, 위험 요소 사전 경고 |
| 외부 계정·결제 | 도메인 구매, DNS, GA·Search Console·카카오·넥슨 API 키, Vercel | 설정값 안내, 등록 후 연결·검증 |
| 운영·홍보 | 홍보 채널 실행 | SEO 설정, 측정 이벤트 설계 |

### 작업 흐름 (한 기능이 나오는 과정)
1. **요청·방향 제시**: "먼작귀로 바이럴 잘될 콘텐츠" 같은 목표를 던짐
2. **AI가 선택지 제안 → 본인이 결정**: 후보별 바이럴 포인트·제작 난이도 비교를 받고 우선순위 결정
3. **리서치**: AI가 공식 자료로 사실 확인, 확인 안 되는 정보는 제외하고 그 사실을 보고
4. **구현 + 자동 검증**: 코드와 함께 "모든 결과가 실제로 나올 수 있는가" 같은 테스트를 작성
5. **시각 확인**: 헤드리스 브라우저로 화면을 캡처해 레이아웃 확인
6. **배포 → 실서비스 점검**: 푸시 시 자동 배포, 배포된 주소로 상태·메타데이터 확인
7. **본인 실기기 검수**: 휴대폰에서 공유·저장 확인, 문제 보고 → 재수정

### AI 결과물을 믿기 위한 장치 (환각·오류 관리)
- **출처 교차 확인 원칙**: 캐릭터 설정은 공식 캐릭터 페이지·위키, 유행어는 월별 트렌드 리포트·기사로 두 곳 이상 확인. 근거가 약한 항목은 제외.
- **추측과 사실 분리 표기**: 팬들의 캐릭터 MBTI는 "공식 설정 아님"으로 표시, 근거가 없는 캐릭터는 MBTI 칸 자체를 숨김.
- **자동 테스트**: FCOSTYLE 단위 테스트 43개(52개 성향×포지션 조합 전부 추천 존재 등), 요즘 유행 테스트 99개(결과 참조·퀴즈 정답 유일성·궁합 28조합 누락 없음·같은 이름=같은 결과 등).
- **시뮬레이션**: (요즘 유행 테스트) 무작위 응답 2만 회로 결과 분포를 측정해 쏠림을 수치로 확인.
- **존재 확인과 실사용 확인 분리**: (FCOSTYLE) 신규 추천 선수가 랭커 표본에서 그 포지션에 실제로 쓰이는지까지 라이브 API로 재검증하는 2단계 기준 수립 (3-9 ③).
- **배포 후 전수 점검**: (요즘 유행 테스트) 사이트맵 전 주소 크롤링으로 상태코드·제목·설명·canonical·H1·구조화 데이터·공유 이미지 확인. AI가 만든 robots.txt 설정 실수(공유 이미지 차단)를 이 점검으로 발견·수정. (FCOSTYLE도 Search Console 실색인 상태로 애드센스 반려 원인 진단, 3-9 ①)

### 본인이 내린 주요 결정 (예시)
- 회사 계정과 개인 프로젝트 분리, 유행 테스트를 FC 사이트와 **별도 프로젝트·별도 도메인**으로 분리
- 캐릭터 공식 이미지 사용 여부 판단(저작권 리스크 설명을 듣고 직접 결정), 공유 카드는 팬아트로 고정
- 도메인 구매처 선택(기존 도메인 관리하던 가비아 → 호스팅과 도메인 분리)
- 콘텐츠 우선순위(먼작귀 → 강아지 확장 20종 → 산리오 → 늙크크 → 먼작귀 바이럴 3종)
- 결과 문구의 톤 방향과 최종 승인
- 늙크크 테스트를 "요즘/옛날 2단계"에서 "지금/올해 초/옛날 3단계"로 개편
- (FCOSTYLE) 커뮤니티 리서치 결과를 기준으로 신규 기능 우선순위를 "카드-포지션 체크 → 스쿼드 체크" 순으로 결정, 시세 데이터는 공식 API 부재로 외부 링크 대체 승인
- (FCOSTYLE) git push 단독 배포 운영 정책 채택

## 이력서 문구 초안
- 한 줄: AI 코딩 에이전트와 협업해 웹 서비스 2개를 기획부터 배포·운영까지 1인으로 런칭 (fcostyle.com, yojeumtest.com)
- FCOSTYLE: Nexon Open API와 직접 수집한 랭커 표본으로 FC온라인 플레이 진단 서비스 구축, 커뮤니티 리서치로 발굴한 신규 기능 출시, 애드센스 반려 원인을 직접 진단해 대응
- 요즘 유행 테스트: 3일 만에 테스트 7종 런칭, 채점 엔진 3종 설계와 2만 회 시뮬레이션 기반 결과 쏠림 보정(최대 30% → 약 10%), 친구 궁합 바이럴 루프·SEO·GA4·카카오 공유 구축, 자동 테스트 99개·배포 후 크롤링 점검으로 검색 노출 결함 4건 수정

## 면접 답변 포인트
- **AI를 쓰면 본인은 뭘 했나**: 무엇을 만들지·하지 않을지를 결정. 주제·차별점·우선순위·톤, 리스크 판단, 외부 계정, 실기기 검수
- **AI 오류 어떻게 걸렀나**: 출처 2곳 교차 확인, 추측 분리 표기, 자동 테스트·시뮬레이션·크롤링 점검, 존재/실사용 2단계 검증
- **가장 어려웠던 문제**: 견종 결과 쏠림 — 숫자로 발견 → 가설 → 방법 변경 → 재측정
- **두 프로젝트 차이**: 데이터 제품(정확성·신뢰) vs 콘텐츠 제품(속도·확산)
- **니즈 파악**: 커뮤니티 조사, 할 수 있는 것(호환성)과 없는 것(시세) 구분
- **성과**: 런칭·인프라·측정 체계까지 완료, 수치는 9장 채워지면 갱신
