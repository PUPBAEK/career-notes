## 2. AI와 일한 방식

### 2-1. 역할 분담 원칙
FC 사이트 초기 기획 문서에 처음부터 명시한 원칙: 개발/콘텐츠/데이터 분석은 Claude와 함께 진행하고, 계정 인증·결제·최종 검수·홍보는 본인이 담당한다.

| 영역 | 본인 | AI (Claude Code) |
|---|---|---|
| 문제 정의·방향 | 주제 선정, 타겟·차별점 정의, 콘텐츠 우선순위 결정 | 후보 비교표·리서치 자료 제공 |
| 리서치 | 최종 채택 여부 판단 | 공식 자료·기사·커뮤니티 교차 조사, 출처 정리 |
| 기획 문서 | 검토·결정 | PRD·IA·정책·데이터 스펙 초안 작성, 결정 사항 반영 |
| 구현 | 결과물 확인·수정 지시 | 코드 작성, 테스트 작성, 리팩터링 |
| 검증 | 실기기 확인(공유·저장·카톡 카드) | 자동 테스트, 시뮬레이션, 배포 후 크롤링 점검 |
| 리스크 판단 | 저작권·광고 정책·개인정보 고지 범위 결정 | 정책·약관 조사, 위험 요소 사전 경고 |
| 외부 계정·결제 | 도메인 구매, DNS, GA·Search Console·카카오·넥슨 API 키, Vercel | 설정값 안내, 등록 후 연결·검증 |
| 운영·홍보 | 홍보 채널 실행 | SEO 설정, 측정 이벤트 설계 |

### 2-2. 작업 흐름 (한 기능이 나오는 과정)
1. **요청·방향 제시**: "먼작귀로 바이럴 잘될 콘텐츠" 같은 목표를 던짐
2. **AI가 선택지 제안 → 본인이 결정**: 후보별 바이럴 포인트·제작 난이도 비교를 받고 우선순위 결정
3. **리서치**: AI가 공식 자료로 사실 확인, 확인 안 되는 정보는 제외하고 그 사실을 보고
4. **구현 + 자동 검증**: 코드와 함께 "모든 결과가 실제로 나올 수 있는가" 같은 테스트를 작성
5. **시각 확인**: 헤드리스 브라우저로 화면을 캡처해 레이아웃 확인
6. **배포 → 실서비스 점검**: 푸시 시 자동 배포, 배포된 주소로 상태·메타데이터 확인
7. **본인 실기기 검수**: 휴대폰에서 공유·저장 확인, 문제 보고 → 재수정

### 2-3. AI 결과물을 믿기 위한 장치 (환각·오류 관리)
- **출처 교차 확인 원칙**: 캐릭터 설정은 공식 캐릭터 페이지·위키, 유행어는 월별 트렌드 리포트·기사로 두 곳 이상 확인. 근거가 약한 항목은 제외.
- **추측과 사실 분리 표기**: 팬들의 캐릭터 MBTI는 "공식 설정 아님"으로 표시, 근거가 없는 캐릭터는 MBTI 칸 자체를 숨김.
- **자동 테스트**: FCOSTYLE 단위 테스트 43개(52개 성향×포지션 조합 전부 추천 존재 등), 요즘 유행 테스트 99개(결과 참조·퀴즈 정답 유일성·궁합 28조합 누락 없음·같은 이름=같은 결과 등).
- **시뮬레이션**: (요즘 유행 테스트) 무작위 응답 2만 회로 결과 분포를 측정해 쏠림을 수치로 확인.
- **존재 확인과 실사용 확인 분리**: (FCOSTYLE) 신규 추천 선수가 랭커 표본에서 그 포지션에 실제로 쓰이는지까지 라이브 API로 재검증하는 2단계 기준 수립 (3-9 ③).
- **배포 후 전수 점검**: (요즘 유행 테스트) 사이트맵 전 주소 크롤링으로 상태코드·제목·설명·canonical·H1·구조화 데이터·공유 이미지 확인. AI가 만든 robots.txt 설정 실수(공유 이미지 차단)를 이 점검으로 발견·수정. (FCOSTYLE도 Search Console 실색인 상태로 애드센스 반려 원인 진단, 3-9 ①)

### 2-4. 본인이 내린 주요 결정 (예시)
- 회사 계정과 개인 프로젝트 분리, 유행 테스트를 FC 사이트와 **별도 프로젝트·별도 도메인**으로 분리
- 캐릭터 공식 이미지 사용 여부 판단(저작권 리스크 설명을 듣고 직접 결정), 공유 카드는 팬아트로 고정
- 도메인 구매처 선택(기존 도메인 관리하던 가비아 → 호스팅과 도메인 분리)
- 콘텐츠 우선순위(먼작귀 → 강아지 확장 20종 → 산리오 → 늙크크 → 먼작귀 바이럴 3종)
- 결과 문구의 톤 방향과 최종 승인
- 늙크크 테스트를 "요즘/옛날 2단계"에서 "지금/올해 초/옛날 3단계"로 개편
- (FCOSTYLE) 커뮤니티 리서치 결과를 기준으로 신규 기능 우선순위를 "카드-포지션 체크 → 스쿼드 체크" 순으로 결정, 시세 데이터는 공식 API 부재로 외부 링크 대체 승인
- (FCOSTYLE) git push 단독 배포 운영 정책 채택

## 3. 프로젝트 1: FCOSTYLE — FC온라인 데이터 분석 서비스

### 3-1. 시작 배경
- 목표: 광고 수익형 웹사이트로 부업 수익 만들기.
- 주제 선정: IT·PM 인사이트, 재테크, 여행, 기기 리뷰, 스포츠베팅 분석 등을 **ICE로 비교**. 스포츠베팅은 애드센스 정책 리스크로 제외. 수익 구조(트래픽 × 페이지뷰 × RPM)와 트래픽 규모별 예상 수익도 계산.
- 인터랙티브 진단 콘텐츠의 장단점을 따져 **재미(진단) + 실데이터(분석) 결합** 방향으로 FC온라인 선택.

### 3-2. 문제 정의와 차별점
- 문제: 유저가 자기 플레이 스타일을 객관적으로 알 방법이 없음. 선수 추천은 커뮤니티 통설 위주. 기존 전적검색 사이트는 스탯만 보여주고 해석이 없음.
- 기회: Nexon Open API가 전체 유저 카드 사용률 같은 집계를 제공하지 않음 → **상위 랭커 표본 수집으로 공백을 메움**.
- 차별점: 실데이터 기반 / 자기 개선형 피드백 / "실제 축구 기준" 큐레이션과 "FC온라인 기준" 실측을 섞지 않고 구분 / 시즌 변경 시 카드 정보 자동 최신화

### 3-3. 타겟 세그먼트
| 세그먼트 | 니즈 | 대응 기능 |
|---|---|---|
| 라이트 유저 | 재미 위주 진단 | 팀컬러 진단 |
| 실사용자 | 내 경기 데이터 기반 분석·개선점 | 실제 매치 기록 진단 |
| 스쿼드 고민 유저 | 포지션별 선수 선택 | 선수 진단, 랭커 정보, 카드-포지션 체크, 스쿼드 체크 |
| 상위권 유저 | 랭커·프로게이머 벤치마크 | 랭커 정보, 프로게이머 비교, 시즌 트렌드 |

### 3-4. 주요 기능
- **실제 매치 기록 진단(핵심)**: 최근 공식경기 최대 20경기 → 승률, 플레이스타일 배지, 슈팅 히트맵, 전략적 피드백(78개 실계정 표본으로 임계값 보정), 나 vs 랭커 35명 vs 프로게이머 22명 비교, 가장 비슷한 프로게이머 매칭, 포메이션별 성과, 스쿼드 기준 추천, 스쿼드 랭커 메타 일치율
- **커스텀매치 상대 전적**, **선수 진단**(2트랙), **팀컬러 진단**(DISC 20문항, 12개 유형)
- **랭커 정보**, **포지션별 카드 티어리스트**, **시즌 메타 변화**
- **카드-포지션 실시간 체크**, **스쿼드 전체 실시간 체크**(닉네임 자동 불러오기)
- **공유**: 링크 복사, 이미지 저장, 결과별 동적 공유 이미지

### 3-5. 데이터 설계
- 실시간: Nexon Open API
- 정적 스냅샷: 랭커 수집 파이프라인 직접 구축, 61명 → UC 시즌 후 재실행으로 **74명** 갱신
- 큐레이션: 기존 108건 + 라이브 검증 49건 = 156건
- 데이터 품질: 신규 49건 전수 재검증, 실사용 미확인 26건 교체

### 3-6. 정책 설계
- **데이터 신뢰도 게이팅**: 최근 30일 + 15경기 이상만 사용, 표본 6명 이하 목록·7명 이상 요약, 3명 미만 "참고용" 배지, 1~2명에 좌우되는 포메이션 제외
- **콘텐츠 정직성**: 근거 출처 배지 의무화, 표본 크기 병기, 소표본 지표 해석 주의 문구, 실측 트랙 성향 필터 개입 금지
- **광고**: 앵커·인페이지만 사용, 전면·의도 기반 광고 비활성화
- **배포 운영**: 로그 대조로 중복 배포 경로 실패 원인 확인 → git push 단독 배포, 이후 동일 실패 0건
- **폐기 정책 기록**: 쓰이지 않게 된 순위 가중치 정책 삭제 및 폐기 이력 문서화

### 3-7. 문서화
PRD, IA, 정책 정의서, 데이터 스펙, 화면 기능 정책, 와이어프레임, DISC 퀴즈 설계, 커뮤니티·프로게이머 리서치 등 총 10종

### 3-8. 제품 진화 (커밋 이력 기준)
초기 기획 → DISC MVP → Open API 실데이터 전환 → 랭커 데이터 → 수익화·운영 기반(도메인, 애드센스 확인, SEO, GTM, 문서화, Vitest) → 애드센스 반려 대응 → 커뮤니티 리서치 기반 확장 → UC 시즌 재수집·포지션 로직 개선

### 3-9. 문제 해결 사례 (STAR)
- **① 애드센스 반려 원인 진단**: "가치가 낮은 콘텐츠" 반려 → Search Console에서 다수 페이지 "발견됨-색인 생성 안 됨" 확인, 필수 정책 페이지 누락·콘텐츠 깊이 부족을 원인으로 특정 → 색인 정상화 확인, 소개·가이드·약관 페이지 신설 후 재신청 준비(결과 대기)
- **② 배포 실패 메일 원인 추적**: 성공/실패 배포 로그 대조로 파일 업로드 방식 중복 경로가 원인임을 확인 → git push 단독 배포 정책, 재발 없음
- **③ 큐레이션 데이터 신뢰성**: 신규 49명 중 26명(약 53%)이 실사용 표본 없음 → 검증 기준을 라이브 API 실사용 확인으로 변경, 26명 전원 교체, 2단계 검증 원칙화
- **④ 포지션 분류 경직성**: RW/RM 등 형제 포지션 정의, 표본 없을 때 형제 포지션 재조회 → 공통 함수 공유하는 3개 기능 동시 개선, GK·CB 등은 형제 미지정으로 과완화 방지
- **⑤ 커뮤니티 리서치 기반 기능 발굴**: 디시·에펨코리아 조사로 스쿼드·카드-포지션 질문 반복 확인, 시세는 공식 API 부재·스크래핑 리스크로 배제 → 기존 실시간 조회 구조 재사용해 신규 기능 2종 출시

### 3-10. 리스크 인식
- 정적 스냅샷 노후화 → 시즌 후 재수집으로 대응
- 닉네임 조회 rate limit 부재 → 트래픽 규모상 보류
- 유입 측정 인프라 부족 → GTM·CTA 이벤트 계측으로 대응
- Vercel 무료 플랜 비상업 조건 → 수익화 시 재검토
- 애드센스 반려 실제 발생 → 사전 준비를 더 보수적으로 했어야 한다는 교훈

## 4. 프로젝트 2: 요즘 유행 테스트 — 트렌드 성향 테스트 플랫폼

### 4-1. 설계 원칙
- 유행이 바뀔 때마다 테스트를 빠르게 갈아끼울 수 있는 구조
- 테스트 하나 = 데이터 파일 하나 → 목록·진행·결과 페이지·사이트맵·공유 이미지 자동 생성
- FC 사이트와 분리된 독립 프로젝트·도메인

### 4-2. 타임라인
- 1일차: 먼작귀 → 강아지 8종 → 20종 → 산리오 → 늙크크 → 이미지 저장 버그 수정 → 첫 배포
- 2일차: 늙크크 3단계 개편 → 도메인 → GA4·개인정보 처리방침 → 소개 → 메타·구조화 데이터 → 색인 점검 수정 → 카카오·X 공유 → 먼작귀 바이럴 3종 → 검색 노출 보강
- 3일차: 전체 재점검, Search Console 사이트맵 제출

### 4-3. 콘텐츠 7종
| 콘텐츠 | 구성 | 채점 |
|---|---|---|
| 먼작귀 성향 테스트 | 14문항, 캐릭터 7명 | count |
| 먼작귀 제초 검정 모의고사 | 15문제, 6등급 | grid |
| 먼작귀 친구 궁합 | 28조합 | — |
| 이름으로 보는 먼작귀 정체 | 이름 입력 | 해시 |
| 강아지 견종 테스트 | 14문항, 20종 | profile |
| 산리오 캐릭터 테스트 | 14문항, 12명 | profile |
| 늙크크 테스트 | 18문항, 7개 결과 | grid(3축) |

### 4-4. 시스템 설계
- 채점 엔진 3종: count(결과 8개 이하, 결과별 최대 점수 균등) / profile(성향 축 프로필 방향 비교, 결과 추가 용이) / grid(축별 % 구간)
- 이미지 교체 구조: 기본 팬아트 SVG, 같은 이름 png·webp 넣으면 자동 교체
- 결과 공유: 결과별 정적 페이지, 개인 응답은 브라우저 세션에만 저장

### 4-5. 문제 해결 사례 (STAR)
- **① 견종 결과 쏠림**: 2만 회 시뮬레이션에서 닥스훈트 약 30%·코기 약 23% → 원인(평균 수렴 + 문항 편향) → 코사인 유사도 + 축별 기준점 보정 → 최다 약 10%·최소 약 2.5%, 20종 모두 1위 가능 자동 테스트로 보장
- **② 결과 이미지 저장 오류**: 디버그 모드로 재현, 원인 3가지(SVG 크기 정보 없음, box-shadow 테두리, 인앱 브라우저 다운로드 차단) → SVG 45장 수정, 저장 흐름 재설계
- **③ 배포 후 검색 노출 결함 4건**: robots.txt 공유 이미지 차단(AI 설정 실수), 내부 링크 0개, vercel.app 중복 노출, 사이트맵 수정일 일괄 갱신 → 전부 수정, 90개 주소 크롤링 점검 정례화
- **④ 카카오 공유 에러 4019**: 공식 문서 대조로 콘솔 설정 문제로 판단 → JavaScript SDK 도메인 미등록 해결, SDK 버전 고정 + SRI
- **⑤ 캐릭터 저작권 리스크**: 공식 이미지 직접 배포 대신 리스크 설명 + 파일 교체 구조 + 공유 카드 팬아트 고정 + 저작권 고지
- **⑥ 유행 신선도**: 2026년 6~10월 트렌드 재조사 → 지금/올해 초/옛날 3단계 개편, "반년 늦은 트렌드러" 결과 신설

### 4-6. 바이럴·성장 설계
친구 궁합 루프, 질문 없는 이름 생성기, 결과별 공유 카드 + 카카오 버튼, 테스트 간 연결

### 4-7. 운영·인프라
Vercel 자동 배포, 가비아 도메인·DNS 직접 설정, GA4 맞춤 이벤트(시작·완료·공유·저장·궁합 완료 등), 검색 노출(제목·FAQ·구조화 데이터·사이트맵 90개·Search Console), 개인정보 처리방침·소개·팬 콘텐츠 고지, 애드센스 준비 전략

## 7. 면접 답변 포인트
- **AI를 쓰면 본인은 뭘 했나**: 무엇을 만들지·하지 않을지를 결정. 주제·차별점·우선순위·톤, 리스크 판단, 외부 계정, 실기기 검수
- **AI 오류 어떻게 걸렀나**: 출처 2곳 교차 확인, 추측 분리 표기, 자동 테스트·시뮬레이션·크롤링 점검, 존재/실사용 2단계 검증
- **가장 어려웠던 문제**: 견종 결과 쏠림 — 숫자로 발견 → 가설 → 방법 변경 → 재측정
- **두 프로젝트 차이**: 데이터 제품(정확성·신뢰) vs 콘텐츠 제품(속도·확산)
- **니즈 파악**: 커뮤니티 조사, 할 수 있는 것(호환성)과 없는 것(시세) 구분
- **성과**: 런칭·인프라·측정 체계까지 완료, 수치는 9장 채워지면 갱신
